Change register ​

Anomalies, features, improvements and discoveries: record, sort, promote and resolve them.

evolution_add ​

effortless_evolution_add — Stability: stable · project

Records a product evolution (type, title, detail, status, reporter, criticality, priority). born_marker (optional): a stable text fragment naming the defect in the git-tracked code; supplied during a work item, it makes the entry be refused if the defect was born from that work (fix it inside). The response carries implication: the suggested verbs, never triggered automatically.

💬 You ask your agent

« Log a bug "CSV export loses accents" with criticality 2, priority 1. »

→ The agent callseffortless_evolution_add
  • type = Anomalie
  • title = CSV export loses accents
  • criticality = 2
  • priority = 1
NameTypeRequiredDescription
typestringyesMarker of the evolution: Découverte, Fonctionnalité, Amélioration, Anomalie or Test. Required.
titlestringyesTitle of the evolution. Required.
detailstringnoDetail text (default empty).
statusstringnoInitial status: Planifié (default), En cours, En Attente, Résolu or Retiré; an active entry whose type quota is full (except Anomalie) is stored as En Attente.
reporterstringnoPerson or agent reporting the entry (free text, optional).
criticalitystringnoCriticality level, an integer from 1 to 3 where 1 is the most urgent; absent leaves the entry unranked.
prioritystringnoPriority level, an integer from 1 to 3 where 1 is the most urgent; absent leaves the entry unranked.
born_markerstringnoStable text fragment naming the defect in the code tracked by git (refusal code, function name, test name). When given, the engine checks whether the defect already existed at the first commit of the active story and refuses the entry if it was born in that work; absent, the entry is accepted with an unclassified note.

evolution_depends_on ​

effortless_evolution_depends_on — Stability: beta · project

Declares what an evolution's graduation must wait for: it is pushed back in the order until the target is closed, without being removed or discounted. An absent or empty target clears the dependency. Refuses an unknown target, a self-dependency and any cycle, at write time.

💬 You ask your agent

« Evolution 26FCT001 must not start before epic 012 is closed: declare that dependency. »

→ The agent callseffortless_evolution_depends_on
  • evo_id = 26FCT001
  • target = 012
NameTypeRequiredDescription
evo_idstringyesId of the evolution that waits. Required.
targetstringnoId of the evolution or epic whose closure releases it; absent or empty removes the dependency.

evolution_edit ​

effortless_evolution_edit — Stability: beta · project

Corrects an evolution: criticality, priority and detail. The previous detail revision is kept append-only in detail_revisions, never overwritten. A terminal status (Resolved or Retired) does not prevent the correction. Does not touch the title, status or type. Refuses a call with no field.

💬 You ask your agent

« Raise evolution 26FCT001 to criticality 1 and replace its detail with: "Also affects the import." »

→ The agent callseffortless_evolution_edit
  • evo_id = 26FCT001
  • criticality = 1
  • detail = Also affects the import.
NameTypeRequiredDescription
evo_idstringyesId of the evolution to correct. Required.
criticalitystringnoNew criticality level, an integer from 1 to 3 where 1 is the most urgent.
prioritystringnoNew priority level, an integer from 1 to 3 where 1 is the most urgent.
detailstringnoCorrected detail text; the previous revision is kept in detail_revisions.

NameTypeRequiredDescription

evolution_migrate_levels ​

effortless_evolution_migrate_levels — Stability: beta · project

Rewrites the registry's legacy levels: converts recognizable free values to integers, maps "Medium" to level 2 (open entries that carried it become Pending, never closed ones) and names in its report every value it could not convert. Idempotent: replayed, it touches nothing.

💬 You ask your agent

« Migrate the registry's legacy criticality and priority levels to integers. »

→ The agent callseffortless_evolution_migrate_levels

No parameters.

evolution_queue ​

effortless_evolution_queue — Stability: beta · project

Read-only. The registry queue: active entries already sorted by the engine key (unmet dependency, then criticality, priority, age, id), bounded and filterable by status and type. Answers "what to pick up next". Compact form, without detail or resolution; an entry is then read by its id. The total is returned next to the window, so a truncated queue is not mistaken for a short one.

💬 You ask your agent

« Which evolution should we pick up next? Give me the first five in the queue. »

→ The agent callseffortless_evolution_queue
  • limit = 5
NameTypeRequiredDescription
statusstringnoKeep only one status; absent returns the queue of active entries.
type_stringnoKeep only one marker: Découverte, Fonctionnalité, Amélioration, Anomalie or Test.
limitintegernoSize of the window, capped at 200 (default 25).
