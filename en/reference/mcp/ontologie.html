Project ontology ​

The ontology schema: layers, atoms and links, proposals and versions, computed progress, alerts, backfill and view.

ontology_add ​

effortless_ontology_add — Stability: beta · project

DIRECT addition or modification of the schema, without changing the version. Reserved to the user: only call on their explicit request; an agent that wants to change the schema goes through effortless_ontology_propose. An atom added this way is born "To review". The ops batch is applied all or nothing. Only this verb accepts set_review ("Validate" / "Back to review").

💬 You ask your agent

« Add the "Automatic assignment" capability to the planning layer. »

→ The agent callseffortless_ontology_add
  • ops = [{"op":"add_object","object":{"id":"affectation-automatique","type":"capacite","name":"Affectation automatique","layer":"planning"}}]
NameTypeRequiredDescription
opsarrayyesThe batch of gestures, applied all or nothing.

ontology_archeo ​

effortless_ontology_archeo — Stability: beta · project

Prepares the schema backfill from the project data: epics, stories, tasks and their states, scopes, decisions, evolutions, global blueprints present; only the references the schema does not cover yet are detailed (covered ones are listed apart), with the contract to follow. Then write ONE source: archeo proposal through effortless_ontology_propose. Refused while an archeo proposal is waiting. In batches: perimeter (epic scope, or registre for evolutions without an epic) or epics (12 or 10-20); with no filter, the first 20 uncovered epics; remaining names the remaining batches. Read-only.

ontology_proposal_accept ​

effortless_ontology_proposal_accept — Stability: beta · project

Accepts a pending proposal: the batch is replayed on the current schema; if it no longer applies, a named refusal is returned and nothing is written; otherwise the schema moves to the next version, the atoms targeted by a framing proposal become "Validated" (an added atom stays "To review" until it is framed) and the history grows. Reserved to the user: only call on their explicit request. A destructive proposal (merging, removing an atom, a link or a layer) needs acknowledge: true, set only once the user has seen its effects; without it, refusal ontology:effetsDestructeurs listing them.

💬 You ask your agent

« I accept proposal ONT-03. »

→ The agent callseffortless_ontology_proposal_accept
  • id = ONT-03
NameTypeRequiredDescription
idstringyesONT-NN.
acknowledgebooleannotrue: the user has seen the proposal's destructive effects and accepts anyway (required for a proposal that merges or removes).

ontology_propose ​

effortless_ontology_propose — Stability: beta · project

The agent proposes a batch of gestures on the schema (add_object, update_object, remove_object, merge_objects, add_link, remove_link, add_layer, update_layer, remove_layer, add_type); the whole batch is validated before being recorded under an ONT-NN number. In full mode, the proposal is accepted automatically and the version goes up; otherwise it waits for the user. An atom targeted by a pending proposal is "Framed". Added atoms stay "To review" even once accepted, until they are framed; only one archeo proposal can wait at a time. The response carries effects: what the batch changes and what it destroys (atom removed or absorbed, link or layer removed, card leaving one of the user's groups). In full mode a proposal is accepted at once, UNLESS it destroys something: it then waits for the user (code ontology:proposedDestructive); tell them what disappears. merge_objects { into, from: [ids] } merges atoms: links, citations and work move to into.

💬 You ask your agent

« Frame automatic assignment: priority 1, code and tests. »

→ The agent callseffortless_ontology_propose
  • summary = Cadrer la affectation automatique
  • source = cadrage
  • ops = [{"op":"update_object","id":"affectation-automatique","set":{"priority":1,"work":["code","test"],"spec":{"text":"Proposer le technicien le plus disponible et compétent."}}}]
NameTypeRequiredDescription
summarystringyesOne sentence: what the batch changes.
sourcestringnoarcheo | cadrage | edition (default) | graduation | plan.
opsarrayyesThe batch of gestures, fully validated before being recorded.

ontology_view_arrange ​

effortless_ontology_view_arrange — Stability: beta · project

The agent arranges the Map in ITS OWN named layout ("Agent proposal — <date>", agent origin), never in Custom nor in the user's work. Without layout, creates the layout from from (Custom by default); with layout, completes an agent layout. Your groups and styles are marked agent there; attaching a card to a user group becomes a suggestion. Any gesture on the user's work (title, style, meta, parent of one of their groups, a style they set, moving a card out of their group) is refused, naming it (ontology:travailUtilisateur). First read effortless_ontology_view_conventions to take inspiration from their colors, groupings and geometry. Also write tour, the guided tour's route: the steps in the order the project is thought through (title, one sentence, groups and cards shown); without it, the tour follows the ① → ⑦ thread by type (ontology:parcoursInvalide if a step shows something that does not exist). effortless_ontology_view_undo undoes the last arrangement. Tell the user the name of the layout and that they keep whatever they want.
