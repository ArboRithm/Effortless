Objectives, milestones and deliverables ​

The steering register of a non-code project: objectives, milestones, deliverables and resources, task effort, deliverable completeness and review.

deliverable_check ​

effortless_deliverable_check — Stability: beta · project

Writes the completeness analysis contract of a deliverable (id: LIV-NN) under .effortless/crew_contracts/_livrables/ and returns its path (prompt_path), the criteria of its type and the shape of the expected report. The agent that follows the contract measures what is present against what is planned, it does not judge quality, then returns its result through effortless_deliverable_report.

💬 You ask your agent

« Is the user guide LIV-01 complete? Run the completeness analysis. »

→ The agent callseffortless_deliverable_check
  • id = LIV-01
NameTypeRequiredDescription
idstringyesDeliverable identifier (LIV-NN).

deliverable_report ​

effortless_deliverable_report — Stability: beta · project

Ingests a deliverable's completeness report: one result per contract criterion (id, status among met, partial, missing, and missing naming what is lacking for any unmet criterion). The rate is computed (met = 1, partial = 0.5, missing = 0). A new report replaces the previous one, and the previous review stops validating. Refused before writing if a criterion is missing, duplicated or unknown.

💬 You ask your agent

« Return the analysis result for deliverable LIV-01: the outline is covered, chapter 2 still has a gap, the brief is respected. »

→ The agent callseffortless_deliverable_report
  • id = LIV-01
  • criteria = [{"id":"plan-couvert","status":"met"},{"id":"sans-trou","status":"partial","missing":["section 2.3 is empty"]},{"id":"cahier-respecte","status":"met"}]
NameTypeRequiredDescription
idstringyesDeliverable identifier (LIV-NN).
criteriaarrayyesOne result per contract criterion, no more, no less.

deliverable_review ​

effortless_deliverable_review — Stability: beta · project

Records the USER's review of a deliverable: verdict accepted or refused, optional note. It is the user's gesture, the only one that makes a deliverable validated: the agent calls it only on the user's explicit request, never on its own after a report. Refused if the deliverable has no report yet, or while the team loop awaits a review that covers it (pilotage:reviewOwnedByLoop: the review is then settled through effortless_crew_review).

💬 You ask your agent

« I have reviewed the user guide LIV-01: I accept it. »

→ The agent callseffortless_deliverable_review
  • id = LIV-01
  • verdict = accepted
  • note = Reviewed, nothing to rework.
NameTypeRequiredDescription
idstringyesDeliverable identifier (LIV-NN).
verdictstringyesThe user's verdict: accepted or refused.
notestringnoThe user's note (optional).

pilotage_remove ​

effortless_pilotage_remove — Stability: beta · project

Removes an object from the steering register (kind: objective, milestone, deliverable or resource; id). Refused while another object cites it (a milestone by an objective, a deliverable by a milestone, a resource by a task): the refusal names the referrers.

💬 You ask your agent

« Remove milestone JAL-03: it is no longer needed. »

→ The agent callseffortless_pilotage_remove
  • kind = milestone
  • id = JAL-03
NameTypeRequiredDescription
kindstringyesObject type: objective, milestone, deliverable or resource.
idstringyesIdentifier of the object (OBJ-NN, JAL-NN, LIV-NN or RES-NN).

pilotage_show ​

effortless_pilotage_show — Stability: beta · project

The steering register (objectives, milestones, deliverables, resources) with its computed state: completeness rate and validation of each deliverable, status of milestones and objectives (a-venir, en-cours, atteint), estimated and spent effort of the work linked to each milestone. Without .effortless/pilotage.json, returns empty lists and writes nothing. Read-only.

💬 You ask your agent

« Where do our objectives and milestones stand? Show me the steering register. »

→ The agent callseffortless_pilotage_show

No parameters.

pilotage_upsert ​

effortless_pilotage_upsert — Stability: beta · project

Adds or replaces an object of the steering register. kind: objective, milestone, deliverable or resource. item: the object; without id it is created with the next identifier (OBJ-NN, JAL-NN, LIV-NN, RES-NN), with an existing id it replaces it. References (an objective's milestones, a milestone's deliverables and work) must exist, and a deliverable's type must be declared by the project model. A deliverable's report and review do not go through this verb. Any refusal happens before writing.

💬 You ask your agent

« Add a deliverable "Write the user guide", of type document, in docs/user-guide.md. »

→ The agent callseffortless_pilotage_upsert
  • kind = deliverable
  • item = {"title":"Write the user guide","kind":"document","path":"docs/user-guide.md"}
NameTypeRequiredDescription
kindstringyesObject type: objective, milestone, deliverable or resource.
itemobjectyesThe object to set (known fields only). Without id it is created with the next identifier; with an existing id it replaces it.

task_effort ​

effortless_task_effort — Stability: beta · project

Sets a task's effort: estimate_minutes replaces the estimate (this verb cannot clear it), add_spent_minutes is ADDED to the time spent (logged_minutes, the same one time tracking feeds), resource assigns a resource of the register (RES-NN) or, empty, removes the assignment. An absent field changes nothing. Any refusal happens before writing; returns the task as written.

💬 You ask your agent

« Estimate task TSK-02 of story 001 of epic 004 at two hours, and assign it to RES-01. »

→ The agent callseffortless_task_effort
  • epic = 004-Epic-Guide
  • story = 001-Story-Writing
  • task = TSK-02
  • estimate_minutes = 120
  • resource = RES-01
NameTypeRequiredDescription
epicstringyesEpic folder, as .effortless/epics/ names it.
storystringyesStory folder within the epic.
taskstringyesTask identifier (TSK-NN).
estimate_minutesintegernoEstimate in minutes: REPLACES the previous estimate. This verb cannot clear it; absent, the estimate does not change.
add_spent_minutesintegernoMinutes spent to ADD to the time spent (logged_minutes).
resourcestringnoAssigned resource (RES-NN, present in the register); empty string: removes the assignment; absent: changes nothing.
