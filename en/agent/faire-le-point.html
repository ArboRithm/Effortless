What the agent does ​

Read the state ​

  1. effortless_status returns the full status: phases, active epic and story, backlog.
  2. effortless_attention returns what awaits you: the work in progress, the open points (questions, recipes to verify, orphan tasks, critical anomalies, git, delivery, drift), the statistics and the queue. An unreadable source is named in skipped.
  3. effortless_project_tree returns the whole tree: epics, stories, statuses.

These three verbs read; they write nothing.

See the modules ​

effortless_modules lists the declared modules: identity (path, languages, model, standards), git state and version, delivery, and the work cited by the commits of their path over 90 days. effortless_widget_list lists the dashboard's custom widgets. Both are read-only.

Pick up the sessions ​

  1. effortless_sessions returns the history, most recent first: the Kessho memory first, otherwise the local sessions of the machine. last gives the latest (title, summary); the reason for a fallback is in skipped.
  2. effortless_session_summary writes the summary of the current session into .effortless/sessions/, local to your machine. Parameter: summary.
  3. effortless_secondbrain_sync archives the project's state (OPALE phase, decisions and tasks of the active story) into your Kessho memory, through Kessho's own server: Effortless never writes into the vault. It writes an archive only if the state changed since the last one; otherwise it answers "up to date". The Kessho project is found by its repository. If it does not exist, the kessho:projetAbsent refusal says so: with your consent, the agent calls the verb again with create: true, which creates it. The context you keep in Kessho is never modified.
  4. Every closed story and epic is also archived in Kessho on its own. Without Kessho, closing still works: its answer says why nothing was archived.

Set the mode ​

effortless_mode_show gives the current mode with its description. effortless_mode_set changes it (full, semi-auto or tutore) and writes it to effortless.json. What each mode allows: see With an agent.

List what Effortless can do ​

effortless_features lists the verb registry. With write_doc: true, it regenerates docs/FEATURES.md and refreshes the derived section of AGENTS.md and the import in CLAUDE.md. Without that parameter, nothing is written.

What you get ​

  • An answer from the agent that names the active epic and story, what is waiting, and the next useful step.
  • A session file in .effortless/sessions/ after effortless_session_summary.
  • An updated work mode in effortless.json.
  • On screen: the Dashboard is the resume screen (in progress, open points, git, statistics); the Backlog shows the tree and the session history; the Modules screen shows the modules; the mode is set in Project settings.
