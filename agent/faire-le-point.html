Faire le point ​

Ce parcours sert à reprendre pied : où en est le projet, qu'est-ce qui attend une décision de votre part, ce qui s'est fait aux dernières sessions. Vous y venez en début de séance, ou quand vous ne savez plus où vous en êtes.

Ce que fait l'agent ​

Lire l'état ​

  1. effortless_status rend le statut complet : phases, épic et story actifs, backlog.
  2. effortless_attention rend ce qui vous attend : l'en-cours, les points ouverts (questions, recettes à vérifier, tâches orphelines, anomalies critiques, git, livraison, dérive), les statistiques et la file. Une source illisible est nommée dans skipped.
  3. effortless_project_tree rend l'arbre complet : épics, stories, statuts.

Ces trois verbes lisent, ils n'écrivent rien.

Voir les modules ​

effortless_modules liste les modules déclarés : identité (chemin, langages, modèle, normes), état git et version, livraison, et le travail cité par les commits de leur chemin sur 90 jours. effortless_widget_list liste les widgets personnalisés du tableau de bord. Tous deux en lecture seule.

Reprendre les sessions ​

  1. effortless_sessions rend l'historique, du plus récent au plus ancien : la mémoire Kessho d'abord, sinon les sessions locales du poste. last donne la dernière (titre, résumé) ; la raison d'un repli est dans skipped.
  2. effortless_session_summary écrit le résumé de la session courante dans .effortless/sessions/, local à votre poste. Paramètre : summary.
  3. effortless_secondbrain_sync archive l'état du projet (phase OPALE, décisions et tâches de la story active) dans votre mémoire Kessho, par le serveur de Kessho lui-même : Effortless n'écrit jamais dans le coffre. Il n'écrit une archive que si l'état a changé depuis la dernière ; sinon il répond « à jour ». Le projet Kessho est retrouvé par son dépôt. S'il n'existe pas, le refus kessho:projetAbsent le dit : avec votre accord, l'agent rappelle le verbe avec create: true, qui le crée. Le contexte que vous tenez dans Kessho n'est jamais modifié.
  4. Chaque story et chaque épic clos s'archivent aussi d'eux-mêmes dans Kessho. Sans Kessho, la clôture se fait quand même : sa réponse dit pourquoi rien n'a été archivé.

Régler le mode ​

effortless_mode_show donne le mode courant avec sa description. effortless_mode_set le change (full, semi-auto ou tutore) et l'écrit dans effortless.json. Ce que chaque mode permet : voir Avec un agent.

Lister ce qu'Effortless sait faire ​

effortless_features liste le registre des verbes. Avec write_doc: true, il régénère docs/FEATURES.md et rafraîchit la section dérivée de AGENTS.md et l'import de CLAUDE.md. Sans ce paramètre, rien n'est écrit.

Ce que vous obtenez ​

  • Une réponse de l'agent qui nomme l'épic et la story actifs, ce qui attend, et le prochain geste utile.
  • Un fichier de session dans .effortless/sessions/ après effortless_session_summary.
  • Un mode de travail mis à jour dans effortless.json.
  • À l'écran : le Tableau de bord est l'écran de reprise (en cours, points ouverts, git, statistiques) ; le Backlog montre l'arbre et l'historique des sessions ; les Modules montrent les modules ; le mode se règle dans les Réglages du projet.

Quand l'agent est refusé ​

SituationCe que dit le refusCe qu'il faut faire
Un verbe de projet est appelé hors d'un projetmcp:racineProjetIntrouvableRenseigner EFFORTLESS_PROJECT si le projet existe ailleurs ; sinon effortless_init en crée un.
effortless_session_summary avec un résumé videsessions:summaryEmptyPasser summary : ce que la session a fait, constaté, en quelques phrases.
effortless_mode_set avec un mode inconnumessage « Mode invalide », sans code ; rien n'est écritPasser full, semi-auto ou tutore.
effortless_features avec write_doc: true sur un fichier non inscriptibleguide:writeFailedRendre le fichier nommé inscriptible, puis rappeler avec write_doc: true.

effortless_status et effortless_features fonctionnent aussi avant tout projet.
