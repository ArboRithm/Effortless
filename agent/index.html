Avec un agent ​

Votre agent IA pilote Effortless par ses verbes MCP : il lit l'état du projet, crée, met à jour, vérifie. Vous décidez, l'agent exécute. L'application montre le même projet, au même moment : tout ce que l'agent fait se voit à l'écran (voir le guide de l'application).

Vous parlez à votre agent en langage naturel. Chaque page de ce guide part de ce que vous lui demandez, puis dit ce qu'il fait, ce que vous obtenez, et ce qui se passe quand un appel est refusé.

Compatibilité ​

Effortless ne cible pas un agent en particulier. Aujourd'hui, les agents qui s'appuient sur des modèles de pointe (LLM « frontier ») sont les plus à même de l'exploiter — Claude Code, Codex ou Antigravity par exemple. L'intégration à opencode est en cours ; selon le modèle utilisé, un fonctionnement similaire n'est pas garanti.

Travailler au mieux : l'agent ouvert à la racine du projet ​

La meilleure expérience d'Effortless s'obtient avec un agent en ligne de commande — Claude Code, Codex ou Antigravity par exemple — dont la session est ouverte à la racine du projet, c'est-à-dire dans le dossier qui contient effortless.json et .effortless/.

Pourquoi la racine :

  • le serveur MCP d'Effortless reconnaît le projet à partir du dossier où la session a été ouverte. Ouverte ailleurs, il ne trouve pas de projet, et ses verbes le disent dans leur refus ;
  • c'est à la racine que vivent AGENTS.md et CLAUDE.md, que l'agent lit au démarrage pour connaître les verbes et la méthode ;
  • l'agent travaille directement dans le code du projet, là où vont ses modifications et ses commits.

En pratique, dans un terminal :

sh
cd ~/Projets/mon-projet   # le dossier qui contient effortless.json
claude                    # ou codex, ou la commande de votre agent

Puis parlez-lui : « Où en est le projet ? » ou « Démarre une story pour le formulaire de devis ». Gardez l'application Effortless ouverte à côté : vous y voyez, en direct, ce que fait l'agent.

D'autres façons de travailler restent confortables :

  • le terminal intégré de VS Code (ou d'un autre éditeur) : ouvrez le dossier du projet (Fichier › Ouvrir le dossier), puis un nouveau terminal — il s'ouvre déjà à la racine. Lancez-y votre agent ;
  • l'extension ou le client de bureau de votre agent, du moment que la session vise le dossier du projet.

Si l'agent répond qu'aucun projet Effortless n'est trouvé, c'est presque toujours que la session n'a pas été ouverte à la racine : fermez-la, placez-vous dans le dossier du projet, et relancez-la.

Connecter un agent ​

Deux voies, qui font le même travail :

  • Depuis l'application : Préférences, catégorie MCP & Skills. Sélectionnez les assistants détectés, puis Déployer (voir Profil et préférences).
  • Par l'agent : effortless_deploy. Sans paramètre, il vise tous les clients détectés sur la machine.

Le déploiement pose :

  • la configuration du serveur MCP Effortless dans chaque client détecté ;
  • un guide global Effortless, entre marqueurs, dans les fichiers d'instructions des agents visés (~/.claude/CLAUDE.md, ~/.config/opencode/AGENTS.md) : le reste de ces fichiers n'est pas touché ;
  • pour Claude Code, une barre d'état Effortless (~/.claude/effortless/statusline.mjs). Si vous avez déjà votre propre barre d'état, elle est conservée : le compte rendu du déploiement vous donne la ligne à poser pour adopter celle d'Effortless.

Après un déploiement, relancez ou reconnectez le serveur dans votre agent pour qu'il voie les verbes.

Dans un projet ​

effortless_init et effortless_features (avec write_doc: true) posent deux fichiers à la racine du projet, entre marqueurs, sans toucher au reste :

  • AGENTS.md : le registre complet des verbes, dérivé du moteur. C'est ce que l'agent lit pour savoir quoi appeler.
  • CLAUDE.md : il importe AGENTS.md (ligne @AGENTS.md), pour les agents qui lisent ce fichier-là.

Ne les éditez pas entre les marqueurs : la section est régénérée.

Modes de travail ​

Le mode se règle par projet, dans Réglages du projet (voir l'écran) ou en le demandant à l'agent (effortless_mode_set).

ModeCe que l'agent peut faire
FullAvance de façon autonome, sans validation intermédiaire.
Semi-autoPropose, et vous validez les jalons clés. Les outils d'exécution sont désactivés : la boucle équipe, l'exécution d'une livraison, la promotion publique. Le déplacement du code vers codebase/<stack>/ ne s'exécute pas non plus.
TutoréPas à pas pédagogique : chaque étape est expliquée et confirmée.

Vous gardez la main ​

Les actions sortantes ou irréversibles (commit, push, tag, release, publication) ne sont faites par l'agent qu'après votre accord explicite.

Quand un appel est refusé, le refus dit deux choses : un code (la cause) et un act (ce qu'il faut faire pour que le même appel réussisse : un autre verbe, ou un argument à corriger). Votre agent s'en sert directement ; chaque page de parcours liste les refus réels de ses verbes.
