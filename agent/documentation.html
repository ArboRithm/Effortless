Documentation ​

Ce parcours couvre trois choses : lire la documentation de cadrage de votre projet, tenir sa documentation utilisateur (celle que lisent vos utilisateurs), et traduire l'interface et les descriptions des outils. Vous y venez pour retrouver un document, vérifier que la documentation suit le produit, ou ajouter une langue.

Ce que fait l'agent ​

Lire et chercher la documentation de cadrage ​

  1. effortless_project_docs_list liste les documents de cadrage du projet : les fichiers à la racine de blueprints/ dont l'en-tête porte type: cadrage-projet.
  2. effortless_docs_list liste tous les documents Markdown de blueprints/, sous-dossiers compris, avec leur titre.
  3. effortless_docs_search avec query cherche dans ces documents, sans tenir compte de la casse ni des accents. Les résultats sont classés par nombre d'occurrences, chacun avec un extrait.
  4. effortless_doc_read avec rel_path (relatif à la racine du projet) lit un document. Il refuse tout chemin hors de blueprints/.

Ces quatre verbes ne font que lire.

Tenir la documentation utilisateur ​

La documentation utilisateur est déclarée dans un fichier userdoc.json à la racine d'une stack. Les quatre verbes prennent stack_id ; sans lui, l'agent vise la seule stack qui déclare une documentation utilisateur.

  1. effortless_user_doc_inventory lit et valide l'inventaire déclaré, et résout chaque source une fois.
  2. effortless_user_doc_coverage fait le diagnostic : trous (une source que personne ne documente), pages vieillies (la source a bougé depuis la génération), pages orphelines (la source a disparu). regime vaut observation (par défaut : les constats sont rendus sans bloquer) ou publication (les constats bloquent).
  3. effortless_user_doc_manifest avec output_dir (relatif à la stack, sans défaut) clôt un build déjà produit : il interroge la paire de versions par la commande déclarée et écrit le manifeste en dernier. S'il ne peut pas le produire, il retire toute la sortie.
  4. effortless_user_doc_sync avec source_dir, staging_dir et current_dir installe une copie hors ligne : la candidate est écrite en préproduction, son manifeste est relu, et la version de format est demandée à la coque. Une copie d'un autre format est refusée et la copie en place est conservée.

Traduire l'interface et les descriptions des outils ​

Deux surfaces se traduisent : front (l'interface) et mcp (les descriptions des outils). Le français est la source ; il ne s'écrit jamais.

  1. effortless_i18n_status avec surface et lang rend le delta : les clés absentes (avec leur texte français) et les clés traduites par machine qu'aucun humain n'a relues.
  2. L'agent traduit lui-même ce delta, puis appelle effortless_i18n_apply avec entries (des clés plates vers le texte). Les traductions vont dans ~/.effortless/locales/<surface>/<lang>.json et sont marquées « machine ». Avec reviewed: true, elles sont marquées relues par un humain, et ne sont plus écrasées par une traduction machine.
  3. effortless_i18n_export rend le catalogue complet (livré et vos ajouts) d'une surface et d'une langue, pour inspection ou sauvegarde.

Ce que vous obtenez ​

  • Des documents retrouvés et lus sans que vous ouvriez le dossier blueprints/. Ils se lisent aussi dans l'écran Connaissance (lentilles de cadrage et champ de recherche).
  • Un diagnostic de couverture avec un code de sortie : conforme, trou, vieillie, orpheline, ou l'un des refus (inventaire invalide, mesure impossible, page altérée).
  • Un manifeste de build et une copie hors ligne installée, quand vous les demandez.
  • Des fichiers de traduction dans votre dossier personnel, sans toucher au code livré.
