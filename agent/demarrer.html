Démarrer ​

Ce parcours sert à ouvrir un chantier : créer un projet neuf, prendre en charge un projet qui existe déjà, ou relier Effortless à votre agent. Vous y venez une fois par projet, ou une fois par machine pour le déploiement.

Ce que vous demandez à l'agent ​

💬 Vous demandez à l’agent

« Crée un projet Effortless ici, avec le modèle tauri-react-tailwind. »

→ L’agent appelleeffortless_init
  • model_id = tauri-react-tailwind
💬 Vous demandez à l’agent

« Quels modèles de stack existent ? Montre-moi le détail de rust. »

→ L’agent appelleeffortless_stack_model_list
💬 Vous demandez à l’agent

« Ce dépôt existe déjà : prépare sa migration vers Effortless, sans rien écrire pour l'instant. »

→ L’agent appelleeffortless_migrate_init
  • confirm = false
💬 Vous demandez à l’agent

« Applique la migration. »

→ L’agent appelleeffortless_migrate_apply
  • dry_run = false
💬 Vous demandez à l’agent

« Mets ce projet à niveau avec la version courante d'Effortless. »

→ L’agent appelleeffortless_migrate
  • confirm = true
💬 Vous demandez à l’agent

Ce que fait l'agent ​

Créer un projet neuf ​

  1. effortless_stack_model_list liste les modèles disponibles (utilisable avant tout projet).
  2. effortless_stack_model_show détaille un modèle : variables, stratégie de build, cycle test/lint/run. Paramètre : model_id.
  3. effortless_init crée le projet dans le répertoire courant. Il passe model_id pour appliquer le modèle (arborescence et normes sous .ai/ndd/), et peut passer project_name, description, context (greenfield, existing ou migration). Il pose aussi AGENTS.md et CLAUDE.md (voir Avec un agent).

Reprendre un projet existant ​

  1. effortless_migrate_init analyse le dépôt. Avec confirm: false (défaut) c'est un aperçu sans écriture ; avec confirm: true il pose la configuration, un épic, une story et migration_plan.json.
  2. effortless_migrate_apply exécute les déplacements du plan. Avec dry_run: true c'est un audit ; avec dry_run: false il déplace réellement les fichiers et écrit migration_report.md.
  3. effortless_codebase_relocate, si vous le voulez, range le code racine sous codebase/<stack>/. dry_run vaut true par défaut.

Mettre un projet à niveau ​

effortless_migrate rejoue les migrations jusqu'au schéma courant. confirm: false (défaut) montre ce qui serait fait ; confirm: true l'applique, avec des sauvegardes .bak. Les anciens verbes effortless_migrate_nomenclature et effortless_migrate_state sont dépréciés : ce sont des alias de effortless_migrate.

Déployer ​

effortless_deploy installe le serveur chez vos clients, le guide global et, pour Claude Code, la barre d'état (voir Avec un agent). targets limite les clients visés, scope choisit user (défaut) ou un projet, grant_permissions: true pose aussi les permissions du serveur. C'est une action sur votre machine : l'agent la lance à votre demande.

Ce que vous obtenez ​

  • Un projet avec effortless.json, .effortless/, l'arbre de dossiers du modèle et, si le modèle en porte, les normes sous .ai/ndd/.
  • AGENTS.md et CLAUDE.md à la racine.
  • Pour une reprise : migration_plan.json, puis migration_report.md une fois le plan appliqué.
  • À l'écran : le projet s'ouvre depuis le sélecteur d'espaces de travail (Ouvrir un espace de travail) ; le déploiement se voit dans Préférences › MCP & Skills (Profil et préférences).
